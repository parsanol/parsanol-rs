## Honest analysis

**parsanol loses to both industry baselines on JSON.** This is the
first quantified SOTA gap and the reason the suite exists.

- **tree-sitter (0.030 µs/B):** a generated LR-family table automaton in
  C. JSON is deterministic, so LR parsing wins categorically — no
  backtracking, no memoization, a tight state-machine loop. Its output
  is a *concrete* syntax tree (every token a node); parsanol produces a
  *typed AST* from the grammar's rule structure, so the comparison
  overstates tree-sitter slightly, but not by 36×.
- **Lark LALR (0.347 µs/B):** the same LR story, in pure Python —
  table-driven determinism beats a backtracking VM by 3× even across an
  interpreter gap. This row is the one to internalize: **it is not the
  language, it is the strategy.** Ordered-choice PEG evaluation pays a
  structural tax on deterministic grammars.
- **Interpreter beats the VM (0.858 vs 1.086):** the VM's crossover wins
  (rs#512) came from regex-dense paths; JSON's grammar is choice-dense
  (value = object|array|string|number|literal, evaluated at every node),
  where the interpreter's direct dispatch is cheaper. Two engines, two
  workload profiles — both rows stay published.

## Where the gap lives (profile notes)

The parsanol cost profile on JSON is dominated by per-node choice
dispatch and arena traffic, not character scanning. Concrete follow-ups
this receipt motivates:

1. **Determinism detection → LR-style fast path.** When a choice set is
   first-set disjoint (as JSON's `value` is), ordered choice collapses
   to indexed dispatch. This is the single biggest lever and it is
   derivable from the grammar at compile time.
2. **VM choice-dense path.** The rs#512 crossover optimized
   char-class-heavy loops; choice dispatch needs the same treatment
   (threaded dispatch, no per-choice resume-slot churn).
3. **Tree construction cost.** parsanol builds typed nodes; if the
   runner's asserts could parse to *end positions only* (no AST), the
   residual would isolate pure recognition cost. A `--no-ast` measure is
   planned so future receipts can split recognition vs construction.
