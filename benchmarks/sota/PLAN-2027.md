# GOAL: parsanol SOTA 2027 — finish all remaining work

## The mission

Make parsanol the measured 2027 state of the art in parsing, and make the proof
public. "Measured" means: one checksummed artifact per grammar; byte-identical
parse trees in every runtime (Rust, Ruby, Python, TypeScript node, TypeScript
web); and published benchmark receipts in this repository that beat tree-sitter
on the three axes that matter — steady-state throughput, error recovery, and
incremental re-parse. Prose claims are not SOTA; numbers under
`benchmarks/sota/results/` are. When this goal is done, `TODO.sota` and
`TODO.perf` have zero open nodes, every entry in them is either shipped with a
receipt or explicitly closed with a recorded reason, and the latest release
train sits on all five registries with `ENGINE-COMPAT.json` green in CI.

## Where we stand (do not re-derive this)

The engine is ahead of tree-sitter on the headline number and the hard
infrastructure is already live:

- **Throughput.** The string-scan shape (option A) ships: quote-delimited
  named rules lower to ONE whole-string span driven by the shared detector and
  escape-aware kernel in `string_shape.rs`, used by both the packrat walker
  and the VM. Measured 0.0177 µs/B on the artifact json workload — roughly
  half of tree-sitter's cost per byte. The DFA table backend (rs#574 stages
  1–7) holds 0.0372 µs/B = 1.05× of tree-sitter on the DFA-heavy lane. The
  classic tag cache (TagKind dispatch + interned-index slots in both the
  walker and the VM) took ~5% off both tiers.
- **The LR lane is LIVE.** rs#574 slice 3b flipped the gate: the canonical
  LR(1) construction (byte-class lookaheads, ACTION/GOTO tables, the symbol
  interning, conflict refusal) lowers eligible named graphs, the VM executes
  `LrRun` and the walker executes the table path, and the full fleet proof —
  612 lib tests, packrat differential, conformance corpus, fleet surveys,
  incremental edit sequences — runs byte-identical with the lane engaged. The
  engagement census permanently pins ≥1 lowered rule; today it counts 10 fleet
  rules lowering under the STRICT construction. The quoted-string idiom
  detection (`rule_body_is_quoted_string_idiom`) precedes the LR attempt, so
  the ScanUntil contract keeps; the string-shape detector precedes both.
- **What the strict gate refuses.** The non-strict construction exists with
  tests: the shift-preference (the greedy loop), the greedy direction (an
  edge-shift beats a reduce-taken byte), and the same-LHS longest-rhs
  reduce/reduce — the PEG-resolution classes. The seam takes
  naturally-conflict-free graphs only; every resolved class refuses today.
  This refusal is why the json spine (the ws runs, the optional frac/exp
  chain) still routes through the stage-3 shapes instead of the LR tables.
- **Recovery and constrained decoding shipped.** rs#576 recovery-shape parity
  (prefix replay + the windowed TED scorer from rs#527 Gate 3) is merged;
  rs#575 TokenBitmask + MaskEmitter rides every runtime; the Rust-auth
  constrained-decoding lowering is published (latest train 0.20.18 /
  1.3.146 / 0.1.29 / 0.10.50) with export parity sha-pinned.
- **Incremental groundwork shipped.** The retained-tree API plus two cache
  fixes (the strict cutoff; recycle wipes snapshots) are in. The dense-memo
  experiment was measured NEGATIVE (0.40×) and is recorded — do not re-attempt
  it. JIT stays deferred; do not open it to chase a number.
- **Releases.** The 1.5.18 / 1.5.19 / 1.5.20 trains landed on crates.io,
  rubygems, PyPI, and both npm tiers, each with content verification (the
  registry-copy replay via a scratch consumer, the shipped-gem replay, the
  vendor CI 32/32 corpus gate, the PyPI local replay). Today ts#95 merged
  (the per-call depth budget API, `parseShapeWithCallDepth`) and 1.5.21

- **Adoption.** All 44 pubid flavor grammars ported and green. The expressir
  adoption (rs#499) is unblocked except for the remark-attachment port (16
  fixtures); the atomic keyword fix landed upstream (expressir#663).

## The four programs that finish the campaign

Work them in this order. Each ends with a published receipt, not a merged PR.

### 1. The 190-site routing tail (finish the census)

1492 lowering sites are censused; 1302 route; 190 remain. The survey artifacts
and the per-site shape table are in the repo — start there, group the 190 by
shape class, and land tranche PRs smallest-first. For each tranche: route the
shape, the 612-test fleet differential stays byte-identical, the conformance
corpus stays 32/32, and an A/B receipt records the win or the wash. The exit
is either 1492/1492 routed, or every residue site carries a documented refusal
reason in the census (some shapes — semantic predicates, call-site-dependent
graphs — are legitimately unroutable; writing that down IS finishing them).
Keep the class-run law in view: min==1 epsilon-free runs lower naturally;
min==0 keeps the ε and stays strict-refused — that class belongs to program 3,
not to a hack here. No heuristic rewrites, ever: if a lowering needs a special
case to pass the differential, the shape analysis is wrong, fix the analysis.

### 2. Incremental (rs#528): the concrete-tree model to completion

The retained-tree API and the cache fixes are the foundation; what remains is
the concrete-tree incremental model: edits splice at the innermost list
containing the change (the multi-level spine pattern that already shipped),
invalidation walks the affected region only, and the re-parse resumes from the
retained prefix. The strict-cutoff and recycle-wipes-snapshots lessons are the
invariants — encode them as regression specs first, then build. Validate on
the incremental edit-sequence corpora the fleet tests already carry, then take
the receipt: the edit-sequence benchmark versus tree-sitter's incremental
re-parse on the same sequences, quiet machine, published under
`benchmarks/sota/results/`. If a memo layer is needed, remember the dense-memo
negative and design the sparse structure instead. Do not chase the number by
weakening the tree contract: byte-identical trees after every edit sequence is
the gate, and the corpus catches violations.

### 3. The resolved-conflict LR coverage (open the strict gate, carefully)

The machinery exists and is tested; the work is the seam. Add an A/B-gated
path (default off, flipped per grammar class with a receipt) that accepts
LR tables whose conflicts resolve under the PEG-resolution laws, in this
order: (a) the shift-preference for the greedy loop — this unlocks the
json ws-run class, the highest-frequency conflict in the fleet spine; (b) the
greedy direction; (c) the same-LHS longest-rhs reduce/reduce. The proof
obligation per class is non-negotiable: the full 612-test fleet differential
byte-identical, the conformance corpus 32/32 in all four runtime CI gates, and
a targeted A/B on the affected grammars showing the win. The known divergence
classes (the ws-ambiguity, the greedy recovery like "3.e5") are exactly where
canonical LR and PEG disagree — the differential will catch any wrong
resolution law; if it fires, the law is wrong, not the test. The engagement
census pin (≥1, currently 10) should RISE with each class; record the new
count in the receipt.

### 4. The engine stack-bound regression (found finishing ts#95 today)

Depth 400 of a right-recursive grammar fit the shipped wasm at 1.5.16 and
overflows it at 1.5.20 — the per-level frames of the named-dispatch recursion
grew (the LR lane, the string-shape path, the tag cache all add per-frame
cost). The web tier additionally leaves the artifact's ownership guard stuck
after a stack-exhausted call (parsing still works; `free()` throws). Fix both
in the engine: a frame diet on the named recursion (the biggest single
per-level allocation), and release the borrow guard on unwind so a
stack-exhausted call leaves the artifact fully usable and freeable. Acceptance
is the test ts#95 originally wrote: `parseShapeWithCallDepth(nested(400),
budget 8192).ok === true` on BOTH tiers, plus a cross-tier pin that free()
after a stack-exhausted call succeeds. This rides the next train under the
release law below.

## The release law (every time, no exceptions)

Every engine change releases rs + ruby + py + ts TOGETHER, in that train
order, and the numbers only count when they're on the registries. The
mechanics that keep biting: BOTH wasm tiers build via the candidate recipe
(bindgen 0.2.130 + the 8 MiB stack); the lock's probe entry
(`stage-compatibility-wasm-probe`) must STAY for `--locked` — any strip
happens AFTER the copy-back; the armv7-musl PyPI wheel leg may fail on the
pypa image — the #73 gate tolerance (`!cancelled() && needs.wheels.result !=
'skipped'`) handles it, and the audits' red after publish is usually the CDN
race, re-run before diagnosing; release-plz runs serialised (#228) and the
version number is the OWNER'S decision — never pick a major, never assume
semver-theory overrides the house line; the 1.5.x line continues for
mechanical-minor changes. `ENGINE-COMPAT.json` rides every train (engine
commit + all tier versions) and `tools/check_engine_compat.py` enforces it in
CI — after any runtime-only release (like today's npm 1.5.21), a follow-up
manifest ride lands promptly or the rs CI gate goes red. Unicode tables make
checksums ruby-patch-sensitive: pin CI ruby 3.4.8. MSRV pins (sha2 =0.11.0,
proptest =1.10.0) exist because uncommitted lockfiles re-resolve past rustc
1.86 — keep them.

## The laws (they are load-bearing; every one has a scar)

The differential gate is the campaign's spine: byte-identical trees across
the packrat walker and the VM, in all runtimes, on every fleet test — a
lowering that needs a special case to pass is wrong. Every bugfix lands with
a regression spec pinning the exact failure; the corrupted corpus once caught
what the whole crate suite missed. The zero-match loop contract (#637, ruby's
named-loop semantics) is LOAD-BEARING — do not "simplify" it. Single SSOT for
tree shape (the parslet CanFlatten contract), no heuristic rewrites, a perf
budget per release (a train that regresses the receipt does not ship). Fetch
and rebase before every push — the owner lands main pushes, releases, and
corpus re-bakes DURING your session; take theirs on spec conflicts. Never
bulk-revert in a shared checkout; verify every diff hunk is yours. Work in
`~/src/parsanol/worktrees/`, never `/tmp` (it gets wiped), push early. Stage
commits by explicit path, never `git add -A`; verify the staged set. No AI
attribution anywhere, ever. PRs only — never commit to main, never push tags
without the owner's number, never merge outside the explicit release
directive. Never delete files you did not create. Cargo tests run under the
memory cap (`ulimit -v 6GB` via the limited-cargo wrapper) — a VM loop once
hit 24 GB. Anchored-scaling reds under high load are CPU contention: re-run
in isolation before diagnosing. The ts conformance gate walks up the tree for
a parsanol-rs sibling — point `PARG_CONFORMANCE_DIR` at the FRESH worktree,
the stale sibling's edition-1 artifacts will waste an hour.

## Operating cadence

Ship in tranches of hours, not weeks: a tranche is one shape class routed, or
one LR class opened, or one incremental invariant specced — each ending in a
green differential, a merged PR, and a one-line report. Batch releases only
when the engine changed; runtime-only and tooling changes ride without a
train. When a measurement contradicts the plan (a negative A/B, a refused
class, a corpus failure), record it and move on — a falsified experiment with
a number beats a hunch with a paragraph. The quiet machine is the only place
receipts are baked; the busy machine is for correctness gates only. If a
session ends mid-tranche, leave the census count, the branch name, and the
next concrete step at the top of your report so the next session resumes in
one read.
